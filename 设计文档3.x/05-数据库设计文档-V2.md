## 1 状态与适用边界

本文件保留原52表全部字段字典，并对受R01–R14影响的字段在原表位置直接修订；新增9表，共61表。文件名V2是历史命名，不代表内容版本。它是目标设计，不是已执行的DDL。2026-10-28 经用户确认，仅支持全新 61 表数据库；取消旧 52 表升级、历史数据导入和兼容验收，历史 DDL 与旧迁移退出开发输入。

初始化实施需按本文件建立目标逻辑模型及MySQL初始迁移，执行 G1。Alembic 保留用于全新基线版本管理及今后正式版本演进；不实现旧 52 表升级链，不能把“生成文件存在”当作 DDL 验收。

## 3 类型与命名

| 逻辑类型 | MySQL 8.0物理类型/规则 |
|---|---|
| uuid | CHAR(36)，小写带连字符；由应用生成，所有引用列类型与排序规则一致 |
| datetime | DATETIME(3)，UTC；连接会话统一time_zone='+00:00' |
| json | JSON；应用校验DTO/schema，数组/对象形状用JSON_TYPE与JSON_LENGTH等必要约束 |
| bool | TINYINT(1)+CHECK IN (0,1)，不使用BIT位串承载布尔 |
| string | VARCHAR(n)，utf8mb4；大文本LONGTEXT |
| score | DECIMAL(5,2) |
| weight | DECIMAL(4,3)；effective用DECIMAL(12,9) |
| 时间轴 | BIGINT毫秒；原INT可保留时需验证45分钟范围 |

最低要求MySQL 8.0.16，确保CHECK实际执行；当前工程已验证环境为8.0.46。全部业务表使用InnoDB、显式utf8mb4及统一排序规则。JSON字面量默认值写成表达式，例如DEFAULT (JSON_ARRAY())；UTC时间默认CURRENT_TIMESTAMP(3)依赖连接会话固定UTC。业务连接与bootstrap/迁移连接均须设置并验证时区。

`_s`为人设定时长，`_ms`为音视频活动时间。状态小写；服务端校验有限值，禁止NaN/Infinity。JSON字段不是“不需要schema”，结构见11的同名DTO。TINYINT(1)布尔列须约束为0/1；状态VARCHAR列按附录A加CHECK；生成列只由数据库派生，不接收业务写入。涉及跨库FK的UUID、字符串列须统一字符集及排序规则。

## 4 关系、事务与组织边界

department→major/class/user；class.department_id与major一致，student_profile的班级/专业和user.department一致。org_admin必须归属一个院系；sys_admin可NULL，NULL不是“所有院系”的通用权限判断。教师学科和班级关系保留原关联表。

report与attempt双向引用分两阶段加FK：先建report且published/latest为空，再建attempt，最后给report添加引用。只允许引用同report的attempt，应用事务校验并每日对账。certificate_report冻结attempt/score_version，不因当前report变化修改旧依据。

除原事件分区表与明确多态引用外，关系均建物理FK。同实例跨库FK由数据库执行，engine个数不改变它。外键删除策略以RESTRICT/NO ACTION为默认，删除以软删和显式业务清理为主。枚举、CHECK、FK、唯一键在MySQL建真实约束。

## 5 模型变更清单

关键修改：pending教师分可空；training有running生命周期；六维score可空且有availability；AI细则持久化dimension_score.item_scores并归档到attempt.result_json；session固定配置/次数/活动时间；登录权限版本和refresh会话落SQL；媒体上传清单可恢复；证书与成绩事件有版本。

字段下表为本版目标值；与旧字典行之外的历史SQL注释冲突时按本版第7章约束实施。初始数据必须显式提供新增必填组织字段，禁止将历史NULL随意映射到某个真实院系。

## 7 关键CHECK与唯一键（本版完整裁决）

### 7.1 有效主批与空值

```sql
-- MySQL：生成列只在已完成主批上非NULL
active_primary_report_id CHAR(36) GENERATED ALWAYS AS
  (CASE WHEN is_primary = 1 AND status = 'reviewed' THEN report_id ELSE NULL END) STORED,
UNIQUE KEY uk_tr_active_primary(active_primary_report_id),
CONSTRAINT ck_tr_reviewed_score CHECK
  (status <> 'reviewed' OR (total_score IS NOT NULL AND total_score BETWEEN 0 AND 100 AND reviewed_at IS NOT NULL))
```

MySQL使用生成列将不参与唯一约束的行映射为NULL，配合唯一键允许多条非参与行；生成列禁止业务写入。pending/returned可无总分，reviewed必须完整细则且总分服务端算；保留MySQL唯一键unique(report_id,teacher_id)。

### 7.2 活动场次、时段与训练

MySQL通过active_user_id生成列`CASE WHEN status IN ('running','paused') THEN user_id END`唯一约束活动场次。session_time_span通过生成辅助列`CASE WHEN end_at IS NULL THEN session_id END`与唯一键约束每场次最多一条open span。辅助列不计业务字段，但计生成manifest。

training约束：finished必须duration_ms>0、completed_at非NULL且score在0..100；未完成时duration_ms可NULL或真实正值、completed_at=NULL；failed必须error。mock_exam只有finished要求final_score/result非NULL，阶段deadline必须大于phase_started_at。

### 7.3 六维、标准和报告

每个已发布/partial报告六行dimension_score：available对应score非NULL且0..100；unavailable对应score=NULL、reason非空且effective_weight=0。item_scores必须JSON数组。max_score>0；权重0..1，应用校验组内和1并在发布事务锁rubric，不能用单行CHECK宣称验证跨行求和。

scored_by与ai_enabled一致；grade_bands强制JSON对象且三线严格递增。report finished/teacher_reviewed要求final_score/grade/generated_at非NULL；teacher_reviewed还要求存在有效主批与reviewed_at。partial不得有总分/grade；calculating/failed初次可空。已有published成功结果时新attempt运行不把report公开状态改calculating，而是latest_attempt状态单独展示。

每个report同时最多一个queued/running attempt，用MySQL生成report占位列`CASE WHEN status IN ('queued','running') THEN report_id END`与唯一键。AI细则item_id必须属于冻结rubric；result_sha256采用规范化JSON计算，终态快照不UPDATE，只允许补运维标签到独立progress元数据。

### 7.4 媒体与证书

recording uploading/failed可无duration/key；success/transcoded必须duration>0、key非空、sha256有效。media_upload_part(upload_id,part_no)唯一；最后一片以外bytes>=5242880，跨行“是否末片”由complete锁清单校验；part_no必须连续从1，最多10000。

certificate_report至少一条，不能只凭可空FK认为达标。签发时完整六维、verified与等级线在同事务检查；status pending_review公开valid=false。过期按`expire_date <= today`，验真与每日清理同口径。

leaderboard唯一键必须包含(scope,scope_id,period_type,period_key,board,user_id)。同学不同榜/周月周期不能互相覆盖。consumer_receipt的事件去重和源版本高水位分开，源版本比较不能拿班级聚合批次source_version代替单report版本。

核心索引：user(phone)、user(department_id,role,status)；class(department_id,major_id)；session(user_id,status)、session(task_id,user_id,attempt_no)；session_event(session_id,seq)唯一和(created_at)清理；span(session_id,span_no)唯一；media_upload(owner_id,status)、part(upload_id,part_no)主键；attempt(report_id,created_at)、attempt(status,created_at)；report(user_id,generated_at)、report(score_version)；outbox(status,next_attempt_at)、outbox(dedupe_key)唯一；receipt(consumer,aggregate_id,aggregate_version)；teacher_review(report_id,teacher_id)唯一与有效主批唯一。

## 9 运行态与保留

Redis键前缀`ai_teach:{env}`；cache可volatile-lru，queue/lease独立noeviction+AOF。state TTL=场次结束后1小时，运行中刷新；WS序号来自SQLnext_seq，Redis丢失读SQL；eval锁TTL30秒每10秒token续期；预签名URL默认15分钟；上传清单SQL保留24小时未完成，成功清单随录制保留。黑名单不代替SQL session撤销。

原审计180天、导出7天、报告/attempt/行为3年、录制默认180天可续至3年。授权记录保存同账号生命周期并保留撤回证据，具体保留需学校确认；不得把“永久”当默认合规结论。导出过期标expired（export_task.status扩展），不是业务失败；失败error必填，expired不要求error。

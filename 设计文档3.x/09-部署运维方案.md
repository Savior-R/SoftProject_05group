## 1 现状和统一形态

当前已有最小后端与健康探针；正式前端、目标迁移、媒体和评测业务尚未完成，准确进度见 app/IMPLEMENTATION_STATUS.md。app/deploy 已按本基准统一部署入口，但需要经验证的 Linux 发布包、frontend/dist 和目标数据库；不能把部署配置检查或健康通过当作 G1/G2/G6。

| 形态 | 调度 | 存储 | 用途 |
|---|---|---|---|
| A1本机 | 单API，SQL待办+同进程调度，QUEUE_BACKEND=memory | 真实SQL、local_parts | 单用户纵向演示 |
| A2本机Redis | API+arq worker，QUEUE_BACKEND=redis | 同A1、Redis队列/租约 | 异步恢复/限流验证 |
| B试点/生产 | 代理、多API、arq worker、outbox dispatcher | SQL、Redis、私有S3、TURN | 真实多角色，容量按实测 |

Python3.12，FastAPI/Pydantic2/SQLAlchemy2，Vue3+Vite+TypeScript（唯一正式目录 app/frontend，产物 dist）；依赖以验证后的lock固定。队列统一arq，不引入Celery/RabbitMQ。A1的memory只是调度唤醒，业务待办/outbox/评测必须落SQL，重启扫描恢复。

## 2 网络和数据库

公网仅HTTPS/WSS及必要TURN端口，internal路由不进公网。前端同源/api/v1和/ws/sessions/{session_id}；WebRTC媒体直连/TURN独立于WS。SQL/Redis不直接公网开放。

MySQL同实例7库；SQL Server ai_teach内7schema。模型显式schema，DSN可含默认库；schema_translate_map按模型映射决定，不是跨库必要条件。一个engine且账户有权限可执行同实例跨库事务；多个engine不取消数据库FK，但多连接提交不自动原子。业务和outbox在同连接事务，未来拆实例需新ADR。迁移/业务账号分离，7库备份保持一致时点。

## 3 配置契约

| 配置 | 规则 |
|---|---|
| ENV | dev/demo/staging/prod；正式生产统一 prod；mock短信仅demo |
| DB_DIALECT、DATABASE_URL | mysql/sqlserver，驱动DSN；secret注入，日志脱敏 |
| QUEUE_BACKEND | memory单API / redis多进程 |
| REDIS_QUEUE_URL、REDIS_CACHE_URL | 队列/租约noeviction+AOF，缓存独立隔离 |
| STORAGE_BACKEND、MEDIA_ROOT | local/s3；local持久绝对目录，禁止容器临时层 |
| S3_ENDPOINT/BUCKET/REGION、S3_ACCESS_KEY/SECRET_KEY | 私有桶，secret，兼容性实测 |
| JWT_ISSUER/AUDIENCE/SIGNING_KEY | 环境隔离强密钥，轮换kid与过渡窗口 |
| ACCESS_TTL_S、REFRESH_TTL_S | 7200/604800，在线SQL撤销不可关闭 |
| AI_MODE | glm/rules/cached_demo，真实来源标识 |
| GLM_BASE_URL/API_KEY、GLM_TEXT_MODEL/VISION_MODEL/ASR_MODEL | 国内实际账号能力清单冻结；11列候选ID待测 |
| GLM_MAX_TEXT_CONCURRENCY/VISION_CONCURRENCY/ASR_CONCURRENCY | 配额内全局共享，不每报告新建限流器 |
| EVAL_WARN_S/TIMEOUT_S/QUEUE_MAX | 300/600/500，超队列503未接受 |
| LOCK_TTL_S、LOCK_RENEW_S | 30/10，token校验续租/释放 |
| UPLOAD_PART_BYTES、UPLOAD_URL_TTL_S | 8388608/900，非末片≥5242880 |
| RTC_STUN_URLS、RTC_TURN_URLS、TURN_SHARED_SECRET | B必需TURN，前端只获短时凭据 |
| SMS_BACKEND | mock仅demo；生产真实provider |
| CORS_ORIGINS、PUBLIC_BASE_URL | 精确来源，真实HTTPS基址 |

FFmpeg/FFprobe可执行路径、CPU/内存/磁盘/超时纳入配置。缺必需secret应启动失败，不使用固定默认密钥。

## 4 工程交付和启动

实施者须交付如下真实入口、依赖lock、配置样例、双数据库DDL/升级、健康检查；以下既有入口与待交付入口须按实施状态区分：

```text
app/backend/app/main.py          # app.main:app
app/backend/app/worker.py        # app.worker.WorkerSettings
app/backend/requirements.lock
app/backend/alembic.ini
app/backend/app/tools/seed.py    # app.tools.seed
app/frontend/                   # Vue3+TS+Vite，npm ci && npm run build → dist/
app/deploy/compose.cloud.yml     # 经验证 Linux 发布包与 frontend/dist 就绪后检查；不自动迁移
```

启动顺序：备份/确认环境→Python3.12/DB/媒体依赖→secret→迁移与G1→seed manifest→对象存储/Redis/TURN（按形态）→API/dispatcher/worker→静态代理→真实黄金路径。A1单进程且不使用reload录制，FFmpeg等阻塞操作放独立执行资源。

目标工程就绪后，在app/backend运行以下命令，当前不是可执行交付保证：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.tools.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

A2/B另终端同目录启动，A1不启动：

```powershell
.\.venv\Scripts\arq.exe app.worker.WorkerSettings
```

dispatcher租约/选举保障多副本，SQL待办可重新投递丢失唤醒。memory/redis切换先停接新评测、排空或记未完成、停调度、改配置、按SQL恢复；不能两个后端同时发布同generation。

目标/health/live检查进程，/health/ready检查本形态必需SQL/Redis/存储，AI可用性独立指标；这些运维路由见06，不泄露secret。健康通过不等于业务验收。

## 5 发布、迁移与回滚

新库从更新后的生成源生成DDL，不再导旧初始化后跳补丁。存量先备份→查双主批冲突→扩展列/新表→院系与状态回填→修主批/训练/六维/导出约束→历史attempt来源回填→校验后收紧。归属不明隔离复核，不随便填院系/满分/verified。

expand/contract发布，MySQL DDL隐式提交与SQL Server事务分别演练。发布前记录DDL manifest/业务基准，发布后验证主批唯一、成绩/证书依据、待办、hash与鉴权。回滚优先兼容代码；新成绩/attempt不能删表式down迁移抹去。不可逆迁移用维护窗口备份恢复，明确新写入RPO和处置，失败停写保现场。

## 6 锁、监控与告警

锁随机token+30秒TTL，每10秒条件续租，失败停止发布，条件释放不能删新持有者锁；SQL唯一/行锁与generation最终兜底。外部429退避仍计600秒预算。

| 指标 | 告警与恢复 |
|---|---|
| 评测端到端/排队/步骤失败 | 300秒告警，600秒本次失败；>500拒新submit |
| provider429/超时/结构错误/费用 | 熔断通知；缺维partial，不填假分 |
| outbox最老待发/死信、投影延迟 | >60秒告警和stale；受控重放，版本去重 |
| session心跳、WS重连/reset、RTC直连/TURN | 重启保守abort，媒体延迟单独统计 |
| 孤儿上传/缺片/hash错、磁盘 | 未完成24小时清理；容量不足停止采集 |
| 鉴权SQL延迟/登录失败/撤销 | 不跳在线校验，告警攻击与锁定 |
| SQL连接/锁等待、Redis内存/AOF、S3错误 | 容量与恢复，队列不随缓存淘汰 |

日志贯通request_id/user/session/attempt/event/score_version，手机号/provider响应脱敏；审计180天追加写，媒体默认180天、最长3年，锁定期与授权规则统一11。

## 7 备份、恢复和容量

SQL每日全备+日志/增量，目标RPO≤15分钟/RTO≤2小时须恢复演练确认；对象版本/删除保护不能代替SQL备份。Redis非唯一事实源，丢失后SQL恢复待办/清单/事件，临时票据重领。

恢复：停写→一致时点SQL与对象清单→校验FK/hash/主批/版本→隔离不完整媒体→重建统计/榜单/曲线→恢复dispatcher/worker→四角色抽验→解除维护。证书依据不完整先pending_review，不能擅自补分。

200场/50路ASR/5分钟报告按G6实测后定容量。4观摩可能消耗多倍学生上行，TURN/转码/S3出口/模型/短信/备份均纳预算，不承诺实时价格/免费额度。

CI：静态/纯函数→DTO/OpenAPI→双方言空库升级→媒体/鉴权/评测→镜像扫描→staging效果/故障/负载→核对G1–G6证据→发布。无门禁证据可继续开发，不得标上线通过。

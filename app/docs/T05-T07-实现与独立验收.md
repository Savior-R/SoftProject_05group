`./wheels/...whl` 是相对路径；这不等于将工作区源码路径写入 lock。

### 4.2 必须执行的空 venv 复验

```powershell
.\.venv\Scripts\python.exe -m tools.verify_install
```

该命令每次新建 `runtime/backend-verification/t05-<随机值>/venv`，仅运行：

```text
python -m pip install --require-hashes --only-binary=:all: -r requirements.lock
```

随后执行 pip check，离开源码目录，以 `python -I` 从已安装包启动真实 HTTP 服务。
成功证据写入 `artifacts/M0/bootstrap/t05-clean-venv.json`，记录新 venv 路径、lock hash、
wheel hash、实际模块路径、HTTP 状态码和日志泄漏检查结果。缓存只复用下载文件，
不会复用任何旧 venv 的 site-packages。

锁定和实测目标为 Windows x64 / CPython 3.12。跨平台或升级解释器须重新验收。

### 4.3 团队成员接收后安装

交付 `app/backend/` 源码、pyproject、两个 lock、`wheels/`，不要交付 `.venv` 或真实 `.env`。
从 backend 目录创建自己的 venv 后：

```powershell
.\.venv\Scripts\python.exe -m pip install --require-hashes --only-binary=:all: -r requirements.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

lock 同时包含开发验收工具，便于每位成员独立复验；不额外执行 editable 安装来掩盖打包缺失。
开发改源码可用 `pip install -e '.[dev]'`，但提交验收前必须重新构建、校验 wheel。

## 7. 常见问题

| 现象 | 排查与处理 |
|---|---|
| Python 版本不符 / py 不存在 | 使用实际 Python 3.12 的完整路径创建 venv；不要依赖裸 python |
| pip 下载失败 | 检查网络、代理、公共 PyPI 可达性；保留失败退出码，解决后重跑；不要禁用 TLS 校验 |
| 缺少相对 wheel / hash 不匹配 | 从 backend 目录安装；同时交付 wheels；用构建工具重新生成，勿手改 hash |
| wheel 过期 | 源码有改动；先 Ruff 格式化、测试，再 build_release，最后重新空 venv 验收 |
| lock 之外又要求手工安装包 | 判为打包/依赖声明缺陷，修 pyproject 和 lock，不能临时 pip install 掩盖 |
| ready 为 503 | 未配置数据库时是正确行为；配置时检查 DSN、异步驱动、端口、权限和连接超时 |
| ready 为 200 但业务失败 | 此阶段只检查 SELECT 1；数据库结构与业务门禁仍需后续步骤实现 |
| 8000 被占用 | 用 Get-NetTCPConnection 检查，改为其他端口；不要终止不属于本任务的进程 |
| PowerShell 提示乱码 | 确认脚本仍为 UTF-8 BOM；不要用会去掉 BOM 的编辑器保存方式 |
| Step 0/2–13 非零 | 正确的未实现阻断；按错误原因实施对应阶段，不改成跳过成功 |
| Step 1 网络不可用 | 空 venv 安装需要依赖可获得；失败应保留失败，不以旧本机 venv 结果代替 |
| pytest 提示默认临时目录/缓存拒绝访问 | 使用 verify-step 的独立目录配置；手工测试可用新建的工作区目录作为 --basetemp 与 cache_dir，不修改其他用户目录权限 |
| 有旧成功证据但当前命令失败 | 以本次退出码为准；核对证据时间与 lock hash，旧证据不代表当前版本通过 |

若公共 PyPI 下载过慢，可显式指定 HTTPS 镜像；仍校验锁内 hash，不能绕过锁：

```powershell
# backend 目录：生成锁/空 venv 复验可分别指定索引。
.\.venv\Scripts\python.exe -m tools.build_release --index-url https://pypi.tuna.tsinghua.edu.cn/simple
.\.venv\Scripts\python.exe -m tools.verify_install --index-url https://pypi.tuna.tsinghua.edu.cn/simple
# 工作区根目录：完整门禁使用相同索引。
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\tools\verify-step.ps1 -Step 1 -PackageIndexUrl https://pypi.tuna.tsinghua.edu.cn/simple
```

### 使用现有本机独立测试库复验

本次临时认证账户已删除，不作为团队长期凭据。可在后端私有 `.env` 填写
TEST_DATABASE_URL，或在项目根目录用已有、不入库的 runtime/local-db.env 设置当前会话：

```powershell
Set-Location -LiteralPath 'D:\soft\HomeWork\SoftProject'
$localDb = @{}
Get-Content -LiteralPath '.\runtime\local-db.env' | ForEach-Object {
    if ($_ -match '^\s*([A-Z_]+)\s*=\s*(.+)$') { $localDb[$Matches[1]] = $Matches[2].Trim() }
}
$dbUser = [Uri]::EscapeDataString($localDb['DB_DEV_USER'])
$dbPassword = [Uri]::EscapeDataString($localDb['DB_DEV_PASSWORD'])
$env:TEST_DATABASE_URL = ('mysql+aiomysql://{0}:{1}@{2}:{3}/test_identity_org' -f `
    $dbUser, $dbPassword, $localDb['DB_DEV_HOST'], $localDb['DB_DEV_PORT'])
# 不打印变量；不把命令展开结果或口令写入日志。
try {
    & powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\tools\verify-step.ps1 -Step 1
    if ($LASTEXITCODE -ne 0) { throw 'Step 1 未通过，请检查本轮脱敏证据与退出码。' }
} finally {
    Remove-Item Env:\TEST_DATABASE_URL -ErrorAction SilentlyContinue
}
```

应已存在 test_identity_org 且账户具备连接权限；本命令不创建数据库、不修改共享账号。
缺少此配置时增强门禁返回失败是预期行为，不能恢复“未配置则跳过成功”。

## 1 背景

设计文档 3.2.0 已定架构方向（FastAPI 单体 + 七域 + MySQL），但没有冻结具体版本、安装位置、依赖锁方式和本机形态。六人若各自装不同版本，会在第一次集成时互相踩踏。本 ADR 把"能开工"的最小基线钉死。

## 2 决策

### 2.1 运行时版本

| 组件 | 决策 | 理由 |
|---|---|---|
| Python | **3.12.10**，装在 `D:\soft\DevEnv\Python312`；全组统一调用 `py -3.12` | `pyproject.toml` 声明 `>=3.12,<3.13`；机器上 Miniconda 是 3.14，**不改用 3.14 绕过基线** |
| Node | **v24.19.0 LTS**，装在 `D:\soft\DevEnv\Node` | 偶数版本属 LTS 线；不依赖 WorkBuddy 自带运行时（`.workbuddy\binaries\node`，会随应用更新漂移） |
| npm | 11.17.0（随 Node） | 统一用 `npm ci` 安装，不用 `npm install` 改 lock |
| Git | 2.55.0 | 行尾规则见 `.gitattributes` |
| FFmpeg / FFprobe | 6.1.1-essentials，`D:\soft\DevEnv\ffmpeg\bin` | 已在用户 PATH；媒体探测必须用 FFprobe，不靠改扩展名 |

### 2.2 唯一数据库与形态

| 项 | 决策 |
|---|---|
| 唯一开发/交付数据库 | **MySQL 8.0**，Docker 容器 `ai-teach-mysql`，**主机端口 3307** → 容器内 3306 |
| 七域映射 | 同一实例内七个 database：`identity_org`/`task_content`/`classroom`/`media`/`evaluation`/`growth_cert`/`platform` |
| 测试隔离 | 独立测试库组（前缀 `test_`），入口必须校验 allowlist，禁止对开发库执行 drop/truncate |
| 范围 | 仅MySQL 8.0全新61表初始化；取消第二方言与旧52表升级，G1按MySQL完整验收 |
| 连接方式 | 业务事务采用 SQLAlchemy 2 同步 Session；不在 async WS 协程内做阻塞查询。现有异步健康探针为独立运维连接，不提供业务 Session、不参与业务事务；见 ADR-012 |

> 不采用"七个独立数据库服务器"：设计要求同一实例内允许跨 schema 物理外键与本地事务，七个独立实例会直接破坏这一点。

### 2.3 依赖锁定方式

- 后端：`pyproject.toml` 声明范围，`pip-compile` 生成 `requirements.lock`，**只有 A 能改**；
- 前端：`package.json` + `package-lock.json`，首次由 A 生成，之后全组 `npm ci`；
- 新成员安装：从 backend 目录执行 `pip install --require-hashes --only-binary=:all: -r requirements.lock`，同时交付相对路径项目 wheel，不额外用 editable 安装掩盖打包问题；
- 换平台（Windows/Linux）需分别生成并验证 lock，**不宣称单份 lock 跨平台已验证**。

### 2.4 前端工程

- 唯一正式 UI：`app/frontend/`，Vue 3 + TypeScript + Vite + Vue Router + Pinia + ECharts；
- 不使用 `app/web/`（09 号另一交付形态），如后续需要另立 ADR；
- 类型由 OpenAPI 自动生成（`src/types/api.generated.ts`），**六人不得手改**。

### 2.5 A1 单机形态约束

| 约束 | 具体 |
|---|---|
| 进程数 | 一个 API 进程，一个同进程调度器；不做多副本 |
| 任务来源 | SQL 的 outbox/待办是事实源，内存只作唤醒，重启必须能从 SQL 恢复 |
| 录制期 | 不使用 `--reload`，避免热重载打断录制 |
| 媒体 | 私有目录 `runtime/media`，不挂 `StaticFiles`，回放必须鉴权 + Range |
| 密钥 | 只在后端 `.env`，不进前端、不进仓库、不进日志 |

### 2.6 环境变量命名

沿用 09 号既定键名，本工程新增 `TEST_DATABASE_URL`。键名完整清单见 `app/backend/.env.example`。
当前只消费最小后端所需配置，其余键在相应业务步骤实现；列出键名不等于业务完成。
ENV 支持 dev/demo/staging/prod；增强 Step 1 必须配置白名单内的独立测试库。

### 2.7 Git协作与可回溯交付（2026-10-28冻结）

- 采用唯一策略：`main`为可发布集成点，成员从最新main创建`codex/<任务简述>`短分支；不另设develop。
- main通过PR集成，至少一位非作者复核；远端分支保护由仓库维护人在main创建后配置并实际确认，不以本文代替设置已完成。
- 任务提交包含必要源码、测试、配置样例、项目wheel及lock；不得提交`.env`、私有媒体、runtime、artifacts或本地工具记忆。
- 提交说明采用`类型(范围): 内容`，如`fix(bootstrap): isolate application factory`；PR列出改动、依赖基线、数据库／契约影响、验证结果、证据位置和未完成项。
- 首次交付先复测并提交基线，随后状态记录引用该基线commit。完整证据仍在被忽略的artifacts中；仓库保留脱敏摘要、复跑命令和待验范围，其他成员自行复跑或通过团队受控位置取得证据。
- 本次用户已授权当前阶段修复及首次提交；只使用用户提供的作者信息，不推断邮箱。远端地址由用户提供；未配置身份、远端或权限时，分别记录，不将本地提交等同于队友已可clone。

### 2.8 应用工厂与依赖索引（2026-10-28）

- `app.factory:create_app`是无运行配置加载副作用的导入入口，测试从此导入。运行入口`app.main:app`保持兼容，并在真实创建应用时执行生产配置校验；不放宽强密钥要求。
- 依赖索引优先级统一为显式`--index-url`／`-PackageIndexUrl`、`PIP_INDEX_URL`、PyPI默认值。构建工具、空venv复验与分步脚本一致；索引地址可能含凭据，不写入提交、验收摘要或普通终端日志。

## 3 后果

**正面**
- 六人可以并行开工，不用等别人装环境；
- 版本漂移被 lock 挡住，集成时不会出现"我这里是好的"；
- 数据库形态与设计一致，跨域事务和外键不会到步骤 8 才发现不可用。

**代价**
- 仅承诺MySQL运行与验收；未来引入其他数据库须重新立项评估，不以预留接口代表已兼容；
- Node 24 比设计时代更新，Vite 相关兼容性需在步骤 3 首次构建时实测确认；
- Docker 容器不是 Windows 服务，**每次开机需手动启动 Docker Desktop**（见第 5 节）。

## 4 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 用 Miniconda 的 Python 3.14 | 违反 `>=3.12,<3.13`；科学计算依赖与本项目无关，反而增加体积 |
| 用 WorkBuddy 内置 Node | 路径在 `.workbuddy\binaries` 下，应用更新会改变，六人无法对齐 |
| 七个独立 MySQL 实例 | 破坏单实例跨 schema 外键与本地事务前提 |
| 便携版 MySQL ZIP | 可行但与本 ADR 选定的容器形态不一致；改选需重开 ADR |
| SQLite 代替目标库跑约束测试 | SQLite 无法验证MySQL约束，属无效验收 |

## 5 运维注意（本机）

1. Docker Desktop **必须先启动**，否则数据库不可用；启动方式：双击桌面图标。若从脚本 / 非交互会话启动，进程会被连带回收，需用 `explorer.exe "<安装目录>\Docker Desktop.exe"` 让它脱离父进程。
2. **端口 3306 已被本机既有服务 `mysqlzt` 占用**，因此开发容器改用主机端口 **3307**。不要为了"统一成 3306"去停掉 `mysqlzt`，也不要让容器和它抢端口。
3. 本机曾因 `AppData\Local\Docker\run` 与 `docker-secrets-engine` 下的 `.sock.stale` 残留导致 Docker 启动失败（报错 "access is denied"）。已通过整目录改名 `.bak-20261027` 规避；再次出现时按同样方式处理，**不要删数据库卷**。
4. `D:\soft\DevEnv\Python312` 与 `D:\soft\DevEnv\ffmpeg` 已加入用户 PATH；`py -3.12` 由 Python Launcher 提供。**改了用户 PATH 后，已打开的终端要重开才生效。**
5. **`.ps1` 脚本必须存为 UTF-8 with BOM**。Windows PowerShell 5.1 会把无 BOM 的 UTF-8 按本地代码页读取，中文注释会破坏引号配对，报出一堆看不懂的语法错误。
6. 原生命令（如 `mysqladmin`、`mysql`）往 stderr 写警告时，PowerShell 在 `$ErrorActionPreference='Stop'` 下会当成终止性错误。脚本里统一用显式 `$LASTEXITCODE` 判断，不靠 Stop 抛异常。
7. 步骤2起停用旧`app/tools/init-dev-db.ps1`宽权限初始化。新入口为`python -m tools.bootstrap_db`，默认只预览；显式apply仅创建全新七库及独立迁移/业务账号，拒绝修改既有对象。platform建表后单独交接表级DML，audit_log仅SELECT/INSERT。现有旧账号不会自动收权，需A安排隔离目标交接；完整流程见[步骤2 A交接说明](../步骤2-A公共数据库基础与交接.md)。

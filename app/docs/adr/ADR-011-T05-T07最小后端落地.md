## 核对结果

| 核对项 | 指定文档内容 | 本次实现 |
|---|---|---|
| 解释器/API | 历史设计（已删除）/03 §3：Python 3.12、FastAPI、Pydantic v2 | 一致，项目限定 >=3.12,<3.13 |
| 数据访问方向 | 历史设计（已删除）/03 ADR-002 和 04 §1：SQLAlchemy async | 仅采用独立异步数据库连通性探针，不新增业务 Session、表或迁移；业务事务仍按 ADR-010 同步方案，边界见 ADR-012 |
| 配置 | 历史设计（已删除）/04 §1：pydantic-settings、app/core/config.py | 按任务新建 app/settings.py；core/config.py 仅重导出兼容，不维护第二套配置 |
| 健康路径 | 历史设计（已删除）/00 §5：/healthz | 任务要求 /health/live、/health/ready 为主路径；/healthz 映射 readiness，未连数据库返回 503 |
| 依赖与包 | 历史设计（已删除）/04 §1：pyproject.toml（uv 管理），未要求 common/tools 包 | 按任务用 setuptools 明确发现 app/common/tools，并用 pip-tools 生成带 hash 的 requirements.lock |
| 静态规范 | 历史设计（已删除）/04 文档信息：类型注解、Ruff | 实现类型注解和 Ruff；2026-10-28 删除未纳入依赖/门禁的 mypy 配置，将来增加时须同时实测 |
| secret | 历史设计（已删除）/03 §7：环境注入，禁止入库入仓 | SecretStr、隐藏校验输入、固定启动日志；不记录 DSN/配置对象/异常原文 |

结论：技术方向一致，但路径、配置文件位置、依赖工具存在上述差异，不能宣称三份旧文档
与任务逐字一致。本次明确任务优先；差异保留在本 ADR 与交付说明，旧设计原件已按统一决策清理。
后续业务实现仍须核对 01/05/06/11；本次不裁决它们的业务规则。

## 范围与验收

1. T05：lock 包含相对路径项目 wheel，空 venv 只执行 lock 安装即可获得三个包；
   验证必须从中立目录启动已安装包，防止当前源码目录掩盖打包遗漏。
2. T06：live 与 ready 分离。数据库未配置返回 not_configured；每次 ready 请求执行
   异步 SELECT 1，有超时与失败返回值。成功只证明连通性，未证明 schema/业务可用。
3. T07：Step 1 对应本次最小后端；Step 0 的全组环境/Git验收及 Step 2–13 均未完成，
   返回非零及具体原因。脚本使用 UTF-8 with BOM，兼容 Windows PowerShell 5.1。
4. 当次未改部署与现有数据库，也未运行建库、迁移、AI 或后续业务验收；后续部署入口已按2026-10-28统一决策适配，不能复用当次验收为部署证明。

锁定目标为 Windows x64 / Python 3.12；其他平台须重新生成并实测，不宣称跨平台已验证。

## 3 给B–F的使用约定

统一从`common.model_base`导入Base和类型，表显式指定逻辑schema及TABLE_OPTIONS。不得另建Base/metadata或每域创建独立业务engine。外键必须指向真实模型；循环依赖通过统一迁移处理，不删除FK规避错误。

业务使用同步`def`入口，注入**事务执行器**，在同一回调内创建、使用并结束Session；不要使用提前yield Session的依赖后再交给另一个线程。

```python
from typing import Annotated
from fastapi import APIRouter, Depends
from sqlalchemy import text
from common.db import Database, get_database

router = APIRouter()

@router.get('/example')
def example(db: Annotated[Database, Depends(get_database)]):
    def work(session):
        # 业务变更和outbox写入在这里使用同一个Session。
        value = session.scalar(text('SELECT 1'))
        return {'value': value}  # 显式DTO或独立数据；不返回ORM/Session/Result。
    return db.run(work)
```

回调不可自行commit/rollback/close，也不可调用DDL；事务结束由公共工作单元负责。业务服务接收本事务Session时必须在回调内同步完成，不把它保存到全局、后台任务或其他线程。`db.transaction()`只供受控底层实现，消费方默认使用`db.run()`以检查返回边界。

步骤2不建立通用异步gateway。步骤3将路由/间接依赖及基础守卫接入统一验收；步骤4由B验首个同步业务；步骤6由D+A、步骤8由F+A根据真实场景将**整个db.run调用**交给受控线程，验证事件循环推进及返回边界。更早出现异步消费者时，适配和验证必须前移到合入前。

## 4 配置与最小权限

- `DATABASE_URL`：日常业务账号，推荐mysql+pymysql URL；旧mysql+aiomysql格式兼容解析，内部按用途派生驱动。探针独立连接，不提供业务Session。
- `MIGRATION_DATABASE_URL`：同实例/端口/入口库的专用迁移账号，用户名必须与业务不同，只供开发迁移工具；不放入运行API的生产环境。
- `DB_SCHEMA_PREFIX`：空前缀对应正式逻辑库名；隔离开发可用`test_<组名>_`；禁止任意库名。
- `TEST_DATABASE_URL`、`TEST_DB_SCHEMA_PREFIX`：单独测试七库，禁止和开发库组相交。步骤1原有SELECT 1验证仍只接受固定`test_`七库。
- UTC及InnoDB/utf8mb4/utf8mb4_0900_ai_ci统一；版本最低8.0.16，以真实CHECK生效为准。

旧`app/tools/init-dev-db.ps1`的宽权限初始化已停用，不能继续用它给业务账号GRANT ALL。现有旧账号/库**未被本轮修改**，不能因此声称已满足G1最小权限；需A人工安排新库组/独立账号交接。工具遇到既有对象会拒绝，不替用户删库或重设口令。

新建流程只用于A确认的独立环境：通过本机受控环境提供`BOOTSTRAP_DATABASE_URL`（管理员）、`BOOTSTRAP_MIGRATION_USER`、`BOOTSTRAP_MIGRATION_PASSWORD`、`BOOTSTRAP_BUSINESS_USER`、`BOOTSTRAP_BUSINESS_PASSWORD`。不把口令写进命令示例、Git或日志；迁移与业务密码独立，至少20字符。MySQL DDL隐式提交，失败可能部分创建，必须人工核对，不能声称事务已全部回滚。

## 8 G1测试数据备份／隔离恢复

本工具仅服务05号§G1的新基线授权测试数据。先使用同一冻结迁移在另一前缀的隔离七库创建相同结构和版本，暂停目标所有API/任务写入；备份期间暂停手工DDL。工具与迁移共用命名锁，但该锁不能自动阻止不遵守约定的管理员DDL或业务写入。只允许可信备份，SHA256检测意外损坏，不认证来源。账号、授权、媒体文件和完整生产灾备由步骤12另行交付。

1. 源库61表/冻结快照/版本均通过结构核对后，使用源库组配置运行：`python -m tools.backup_db --purpose test --output ../../artifacts/G1/mysql/source.g1-backup.json`。七库InnoDB数据在同一REPEATABLE READ只读一致性快照中采集，二进制/Decimal/日期时间保留类型，已有备份不会被覆盖。
2. 预览：`python -m tools.restore_db --input ../../artifacts/G1/mysql/source.g1-backup.json`。只校验备份，不连接数据库或修改库。
3. 将本机配置切换到独立目标的`TEST_DATABASE_URL`、不同前缀的`TEST_DB_SCHEMA_PREFIX`及专用`MIGRATION_DATABASE_URL`，目标所有业务表必须为空，迁移版本表保留原版本。运行：`python -m tools.restore_db --input ../../artifacts/G1/mysql/source.g1-backup.json --apply --output ../../artifacts/G1/mysql/restore.json`。
4. 工具核对结构/版本及空表；全七库数据在一个事务恢复，跳过生成列写入并检查其计算结果。为处理合法循环FK，临时关闭本连接FK检查，提交前独立全量核对FK和全部行值，finally恢复FK检查；任何失败回滚本次数据，不做DDL、TRUNCATE或DELETE。重复恢复到非空库会拒绝。
5. 再运行完整`verify_db`、各域约束/关系测试并留存结构、版本、行数、关联及失败恢复证据，才构成完整G1恢复验收。当前只验证四表与专用协议夹具，61表恢复仍待B–F交接；当前CLI缺完整模型/冻结时在连接数据库前拒绝。
